DONE (with key results)
-----------------------
- Schema, 37 criteria, vocabulary.
- Template generator, v0 dataset (3,000 cases).
- v1 and v2 Claude rewrites of dev/test; v2 mean 94 words (range 50-189),
  matched to real recordings (61 / 131 / 223 words).
- 3 real recordings transcribed with Whisper.
- Test set frozen: 1,518 cases + real recordings, hash-checked.
- Train set: 10,000 template cases, no overlap with dev/test. Decision:
  templates only, no Claude-written training text.
- Compact prompt schema: system prompt ~1,550 tokens; all 13,000 gold
  records fit the decoding schema.
- Scoring script, tested on known inputs (gold = perfect, empty = F1 0).
- Rule engine: all 37 criteria. Identical to the reference labeller on
  13,000 complete records; on 12,352 incomplete records the true level is
  always between certain and possible level; 0 silent under-triage.

- Prompt rules: added the generator's labelling conventions (arrival
  mode = ems_scene unless transfer, SpO2 room air unless on oxygen,
  "moving all four" / "abdomen soft" / "breath sounds equal" mappings, ...).
  System prompt ~1,870 tokens (~2,670 with 2 few-shot examples).
- Inference harness: extract/run.py, plumbing tested end-to-end.
- v2 label repair: audit (scripts/audit_v2_labels.py) proposed 397
  label changes where the v2 rewrite dropped or added a statement; each
  reviewed by hand. 381 applied in 311 cases (dev 156, test 155), 16
  rejected as detector false positives. Main fixes: "no injuries" not
  said (84), "signs of shock" said but unlabelled (56), GCS components /
  LOC / bleeding / abdomen / neuro / trend / airway / ETA not said.
  Only said records changed; true records and true levels unchanged.
  scripts/repair_v2_labels.py; backup examples/archive/.
- v1/v2 text-export JSONs moved to examples/text_exports/; full test
  suite passes (5,953).
- Test set re-frozen with documented reason (manifest "history"); no
  model had been run on test.
- E0 regex baseline (v2 dev, repaired labels): field F1 0.990,
  hallucination 0.0%, exact match 30.2%, corrections 99.3%,
  triage accuracy 95.3%, under-triage 4.7%, silent under-triage 0.
  (Before repair: F1 0.986, exact 26.5%, triage 93.5%.) Main weakness:
  injuries, vehicle intrusion. (runs/e0_regex_v2_dev.*)

- First model probe (qwen3:1.7b, think off, 5 dev cases): ~6 s per case
  on the RTX 3050 Ti (~2,450 prompt + ~550 output tokens; GPU 2.9 GB).
  3 of 5 outputs broke a cross-field schema rule that JSON-constrained
  decoding cannot enforce (bone on a non-fracture, vehicle details on an
  assault, intubation with airway "patent"). Added extract/postprocess.py:
  deterministic repair that only nulls or drops the contradicting detail
  (never invents a value). Scorer: status valid / repaired / invalid;
  reports valid_rate (strict) and usable_rate; lists repairs. Tests for
  the repair (tests/test_postprocess.py); suite 5,960 passing (2026-11-04, incl. tests/test_error_analysis.py).
- E2 zero-shot screening (DONE 2026-11-02). Design: full dev takes
  ~2.5 h per 1.7B model, so all 12 models were run on the same first 200
  dev cases (dev order is random). 50-case smoke test first; a model is
  dropped if <80% of outputs are usable or mean time per case >120 s.
  Laptop RTX 3050 Ti 4 GB; think off for Qwen3.

  Findings:
  - qwen3:4b is clearly best, but still below E0 -> E3/E4 needed.
  - Size matters most: every 3-4B model beats every <=2B model on
    triage (65-83% vs 30-54%); over-triage falls from 39-62% to 9-25%.
  - Small models mostly over-triage (wrong/invented findings make a case
    look worse). qwen3:4b is the first with balanced errors.
  - F1 and triage can disagree: gemma3:4b invents many minor details
    (36% hallucination) that rarely change the level.
  - Silent under-triage 0 for all 12 models.
  - Strictly valid output is rare for most models (0-16% for <=2B); the
    repair step makes 88-100% usable.
  Finalists for full dev and E3: qwen3:4b, qwen2.5:3b, llama3.2:3b,
  qwen3:1.7b (fastest that fits the laptop GPU).
- E2 run history (why it took several runs):
  - 3-4B models don't fit the 4 GB GPU and spill to CPU (~40 s/case,
    ~3 h per model); they were paused, then run after the small models.
  - One run was stopped by Claude Code (laptop low on RAM), one by hand;
    runs are resumable (one line per case, done cases skipped).
  - First pass dropped llama3.2:1b, qwen2.5:1.5b, smollm2:1.7b because a
    single runaway case hit the 600 s request timeout.
  - RULE CHANGE (2026-11-01, approved by the user): output capped at
    1,500 tokens (extract/run.py --max-tokens; same as the OpenAI
    backend; normal records 530-900 tokens, p99 < 1,000) and the smoke
    gate uses MEAN instead of MAX latency. The 21 cases that had gone
    over 1,500 tokens or timed out were deleted and re-run under the cap,
    so all models follow the same rule. Pre-cap files:
    runs/archive_pre_cap/. Under the cap llama3.2:1b and qwen2.5:1.5b
    pass; smollm2 is dropped on usable rate.
  - Logs: runs/sweep_dev_k0.log, _small.log, _cap.log. Final table:
    runs/sweep_dev_k0.csv; per model runs/<model>_dev_k0.report.json.

- E0 is optimistic (notebook 10b): its word lists and patterns come from
  the generator. Re-phrased example sentences (own, not from any data
  set) lose BP/HR/SpO2, meds, age and injuries. On the 3 real recordings
  it misses vitals without "BP" labels, "auto crash"/"airbag"
  mechanisms, "forehead" lacerations, "blood thinners", "approximately
  35 years old", and Whisper errors ("rule over", "cool and diverted").
  TEST-SET NOTE (2026-11-02): the regex was run on the 3 real test
  recordings for illustration only (no labels, no score). The regex
  baseline is FROZEN from now on: no changes based on these outputs. No
  model has been run on the real recordings.

- E2 error analysis (DONE 2026-11-04): scripts/error_analysis.py (tests:
  tests/test_error_analysis.py) -> runs/error_analysis/<run>/ (per_field,
  under_triage, corrections CSVs, summary.json) and patterns_dev.csv
  comparing the 4 finalists. Qwen3 4B, 1,482 dev cases:
  - Nested object left null when only part was said: "GCS 15" alone
    missed 48% (3% with components); "no LOC" missed 71%; crash speed
    missed 75% (vehicle object null; always for pedestrian/cyclist);
    "with burns" -> mechanism.type null 86%.
  - Digit amputations recorded on hand/foot instead of finger/toe: 100%
    -> L3-05 never fires; 35 of the 117 under-triaged cases.
  - Systolic 110-119 ("one-fourteen") written as 140 etc.: 52%.
  - Unsaid "normal" values: hemorrhage none 72%, airway patent 43%,
    abdominal pain false 19% -> most of the 4.5% hallucination; they hide
    unknowns from the engine (fewer questions asked).
  - Empty (all-null) records: 30 cases (2%), 26 of them vitals-first calls.
  - Corrections: value right 63%; the 14% correction accuracy is mostly
    the retraction log written in words (122/285); retracted value kept in
    79 (38% of the corrections that cross a threshold).
  - Under-triage 117: empty record, amputation region, crash speed and LOC
    explain 85 (73%); all 117 provisional (silent 0).
  - Other finalists: LOC drop (71-99%), amputation region (43-100%) and
    kept corrections are shared; others are model-specific (llama3.2:3b
    never misreads 11x but misses speed 98%; qwen3:1.7b writes trend
    "stable" 70% when unsaid).
